# v1.2.9 空开机动画槽处理

日期：2026-10-31。

## 触发条件与修复

LG600 REV 0075 反馈截图中的开机动画元数据为 `selector=1`、`size=0`、`active_record=0xFFFFFFFF`、`next_record=0x00400000`。旧版在读取元数据时要求长度大于 0，导致识别、备份和首次写入均提前停止。将该响应回放给未修改的旧版代码，100 次均出现相同错误。

v1.2.9 仅在上述字段匹配、附加字段为 0，且连续两次元数据完全一致时识别为空槽。待机图空槽及其他零长度、错误选择值、未知地址、变化的元数据仍停止。新写入内容仍必须是非空、格式有效且未超容量的素材。

识别显示“尚未保存开机动画”，不请求不存在的首帧。备份中的 `boot.bin` 为零字节，清单保存 `empty: true`、原始元数据及空文件 SHA-256；待机图仍完整读取、验证并保存。首次写入前重新确认当前素材与备份状态一致，随后沿用维护模式 0、8 KiB 分块写入、完整读回及模式 1 流程。

首次 `Original` 记录即使为空也继续保留，不用之后的自定义动画替换。该备份只证明原来没有有效动画，不能用来恢复不存在的旧动画；恢复操作在发送模式或擦写命令前明确停止。只有空槽记录、尚未写入动画时，也不能直接开启或修复离线循环。

## 验证

- 全部 114 项离线测试通过，其中 19 项为空槽新增回归测试。
- 模拟设备验证完整首次写入、逐字节读回、待机图备份、首次原始记录保留，以及中断后不重发擦写、不提前恢复循环。
- 异常元数据、变化的空槽、损坏或伪造的空槽备份、无效待机图、未知固件和空新素材继续被拒绝。
- LG600、LG700、LX800 的真实 Tk 界面均检查空槽提示、控件布局及正常首帧预览切换；此界面验证不访问 USB。
- 本机 LG700 REV 0075 的现有动画为 7,163,382 字节、240 帧，进行了只读元数据与首帧检查。

空槽状态及首次写入流程使用元数据回放和模拟存储验证，没有清空本机真实屏幕。未执行 LG600 空槽实机写入或断电播放测试。反馈截图中的其他写入成功结论未作为本次验证证据。

# 离线循环与写入中断排查（2026-10-25）

## 已确认的现场

- REV 0067 在开机动画的 `0x0B` 数据块写入等待应答时返回 Windows 1167。Windows Kernel-PnP 同时记录 11:59:57 意外移除设备，12:00:00 重新出现。
- 开机区随后返回 size=0、active_record=0xFFFFFFFF，没有有效的已提交动画；这解释了黑屏。待机图写入和读回成功。
- 目标为 10,319,455 字节、324 帧，未超过 11,534,316 字节容量；本地容器和所有 JPEG 验证通过。

## 协议与程序问题

1. 程序原先在原生循环模式 1 下直接写入和读回，没有进入维护模式。厂商 V75 的 `0x12CB64` 在主机活动计数归零、模式为 1、活动标志为 1 时向动画任务发送 `0x19`；任务的该分支执行 reboot 路径。离线仿真确认切换模式 0 会屏蔽这个分支。
2. 模式命令 `0x1E` 的厂商处理分支保存配置但不发送同名 ACK。旧程序却等待 ACK，将正常的无应答当成超时，再重新打开命令口。重新打开句柄不能证明屏幕发生过物理重新连接。

V75 是厂商公开固件，实机为 REV 0067，不能将 V75 静态分析当成实机固件完全一致的证明。故障当时没有开启 USB ETW，旧日志也没有保存失败块偏移；本次中途掉线究竟由上述超时路径、其他固件复位路径还是物理 USB 异常首先触发，尚不能独立证明。

## 修正与实测

- 完整备份并核验后，发送模式 0；在该模式下完成待机图、开机动画的写入与完整读回；全部通过后才发送模式 1。失败时停止，不自动重发擦写，也不自动恢复循环。
- `0x1E` 只发送一次，不等待不存在的 ACK；使用后续版本查询检查命令处理是否正常，仍不声称读回了模式值。
- 写入错误保存 selector、offset、length、是否最后提交及原始异常。保留 8 KiB 读写分块、10 ms 命令间隔和原动画字节。
- REV 0067 完成一次同目标的受控恢复：1,260 个写入块，10,319,455 字节完整读回一致，无重发、无校验重连。SHA-256 为 `74d6dc6a02f779d1ac4cce6b65f913dd15158d19a14dacf50c671a0e7baaf072`。待机图与目标首帧一致。
- 用户确认恢复模式 1 后，实体屏幕动画正常循环播放。27 项离线测试通过。

这是一轮真实恢复写入的验证，不代表所有 USB 环境或所有固件版本均已验证，也不将一次成功对比描述为本次中途断连触发源的完全因果证明。

# LG600 / LX800 适配与验证

初始验证日期：2026-10-26；状态更新：2026-10-29。适配引入版本：1.1.0；当前版本：1.2.7。设备路由、转码尺寸、预览及备份恢复均按独立型号处理。LG600 已由用户反馈 v1.2.7 实测通过；LX800 仍以 V75 固件分析和离线仿真为依据。最新实测范围见 [v1.2.7 实机验证记录](v1.2.7-hardware-validation.md)。

## 型号依据

官方 T'OWEI 软件配置将 LG600 定义为 PID `1520`、480×480，将 LX800 定义为 PID `151D`、480×480；两者 VID 均为 `1A2C`。命令 HID 口是 MI00、usage page FF06、usage 1。串流数据口不用于离线素材写入。

LX800 的圆形主屏使用 480×480 方形编码画布，圆外四角不可见。程序只对本地预览加圆形遮罩，不把 JPEG 改为圆形文件，也不修改设备旋转设置。官方在线串流管线的旋转参数不能直接当作离线素材的旋转依据；真实面板方向仍需持有者确认。侧面状态小屏不在本适配范围。

固件参考来自 [TCOMAS 官方固件下载页](https://www.tcomas.cn/FirmwareUpgradeTest)。LG600 V75 更新包 SHA-256：`3903df2c6180d24cc9d22f6ba07c9eea67e5a5093b22391521b07dc172a6f234`。LX800 V75 更新包 SHA-256：`643334c9e67dfeca701293b674916bf9dd172538dad0a6102504ca2661509403`。两个固件的测试结果见随附 JSON。只提取并离线分析更新包，不运行升级程序，不向设备刷写固件。

两款 V75 的素材区、命令及容器流程相同：

| 项目 | 内容 |
| --- | --- |
| 开机动画区 | `[0x400000, 0xF00000)`，11 MiB，扣除记录头后最大 11,534,316 字节 |
| 待机图区 | `[0xF00000, 0x1000000)`，1 MiB |
| 开始写入 | `0x0A`，selector 1 为开机动画，0 为待机图 |
| 数据/提交 | `0x0B`，8,192 字节分块，最后块进度 100 提交 |
| 元数据/读取 | `0x0C` / `0x0D` |
| 版本 | `0x87`，参考固件返回 `0075` |
| 原生循环 | `0x1E`，0 为维护模式，1 为循环；无应答也无模式读取接口 |
| 素材 | 原厂 16 字节记录目录、基线 JPEG 帧；非 H.264 视频 |

固件二进制不同，不能互刷。共同协议不意味着 NEOX 也可兼容；其固件平台不同，本工具不枚举 NEOX。

## 已完成的代码路径

1. 自动或手动按 PID 选择型号，只打开对应命令口；多个同型号设备也停止。
2. 本地图片/视频按目标尺寸转换，画质、裁剪、缓存与预览一致；LX800 预览模拟圆形可视区域。
3. 默认识别直接读取所选型号硬件动画包的第一帧；不再用官方 `lastPageState` 选中的本地素材替代硬件预览。
4. 写入前确认仍是选定设备，备份两个区域；备份按型号与设备隔离并验证 SHA-256。
5. 完整备份后模式 0，写入开机动画及待机首帧，逐字节完整读回；相同内容全量核验后跳过擦写。
6. 等待待机记录提交 3 秒，再复核待机图，成功后发送模式 1；写入流程在模式 1 启动后不再进行开机区全量读回。独立的轻量识别使用有界首帧双快照，见 [首帧识别说明](first-frame-preview.md)。
7. 原始恢复沿用型号、设备、版本、文件散列及分辨率校验，同样在模式 0 中写入和读回，通过后恢复模式 1。

## 验证方法与结果

型号适配引入时有 44 项离线测试；v1.2.7 共 75 项，涵盖原有 LG700 回归测试、跨型号备份拦截、多设备路由、重连目标保持、未知版本禁止写入、转换期间设备更换拦截、目标尺寸、缓存隔离、圆形预览、首帧校验及已知记录属性兼容。运行方式：`python scripts/run_tests.py`，不连接 USB。

另外，用 Unicorn 执行每款 V75 固件经初始化的真实 ARM 代码：命令组包/分包、命令分派、存储记录、开机容器解析、下一帧读取、末帧回到第零帧、配置记录保存与重载。替换的只是物理 SPI、USB 队列、分配器、调度及显示硬件。实际应用代码通过模拟 HID 与这些固件代码交互，没有在测试时替换产品源码。

两个型号均通过：

- 合成 9 帧视频分别做完整画面和居中裁剪，两种结果均为 480×480；动画包分别为 122,498 / 133,022 字节。
- 程序自动备份旧开机动画和待机图，写入新素材并完整读回，全部逐字节一致。
- 再次应用同一素材未产生虚拟闪存擦写；超容量素材及未知版本被拒绝。
- 程序恢复旧素材并完整读回；真实固件解析 JPEG 帧表，加载的帧字节一致，模式 1 分支从最后一帧回到第零帧。
- 执行固件配置保存函数，重新创建初始化 RAM、复用虚拟闪存，模式 1 及素材记录均正确重载。

这证明代码和参考固件的逻辑相容，**不能替代实机验证**。未模拟真实 USB 调度、闪存器件的忙等待/掉电行为、异步配置保存时机、JPEG 解码显示电路及面板可视区域；仿真本身不确认真实设备版本、实际画面方向或物理断电后的播放效果。2026-10-29 的 LG600 用户实测反馈单独记录于上述实机验证文档；LX800 仍待实机验证。遇到其他 REV 只允许识别与读取，禁止写入及模式修改。

## FFmpeg 与速度

根据用户决定继续采用独立 CPU 版 FFmpeg。新增型号没有改变传输分块、命令等待和固件响应频率，不宣称本版本可缩短永久写入耗时。原厂在线切换画面与离线持久写入是不同流程。

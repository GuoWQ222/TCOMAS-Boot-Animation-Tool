# v1.0.1 通信验证记录

## 观察到的问题

LG700 REV 0067 在完整读取期间曾返回旧的 `0x0D` 续包，使后续读取或 `0x0C` 元数据查询超时。Windows 端重新打开 HID、清理缓冲、重连指定 USB 端口或重启指定设备，均未在该次卡住状态下恢复正常查询；真正切断屏幕供电后可以重新通信。

独立 Windows HID 实现使用 512 个接收报告缓冲后，两轮读取可以结束，但两次内容不同，且都与目标文件不完全一致。测试期间没有发送素材写入、擦除、复位或播放模式命令，因此存在读取通路的瞬时错误，不能据此认定已保存的动画损坏。报错进度也不能直接当作写入完成比例。

## 本版改动

- Windows 直接使用系统 HID 与异步 I/O，接收缓冲为 512 个报告；超时 I/O 取消后等待其结束。
- 完整命令之间保留至少 10 毫秒处理间隔，为设备完成上一条命令留出时间。
- 保留 8,192 字节读写分块和原有 JPEG/视频转换参数；不以降低画质处理通信错误。
- 保留严格的偏移、长度、包序、状态和元数据检查；擦写、提交及模式命令不盲目重发。
- 显示具体素材的操作阶段，区分待机图与开机动画。

这些改动在下述条件下通过验证；设备内部产生错位的确切原因尚未独立证明。

## 验证边界

该轮早期通信验证当时未进行新的硬件擦写，界面保留“通信修复测试版”标识；当前保护版的后续恢复写入验证见本页开头链接。v1.0.0 的既有写入验证不能替代新传输实现的写入实测，也不代表其他型号、固件或 USB 环境已验证。

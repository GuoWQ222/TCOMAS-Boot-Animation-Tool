# 轻量硬件首帧识别

v1.2.5 修复了预览来源混淆：此前识别设备后，再从官方软件的本地配置读取其选中的视频，导致硬件已保存动画与预览不一致。该预览既不是硬件素材读取，也不是捕获 USB 实时传输帧。

当前默认识别直接读取硬件动画包：

1. 查询设备型号、固件和开机动画元数据。
2. 读取 16 字节包头及首条目录记录，校验帧数、容器长度、首帧偏移与大小。
3. 按已验证的 8 KiB 上限读取第一帧 JPEG；不读取整个帧表或后续帧。
4. 检查 JPEG 格式、目标尺寸及解码完整性，重复读取这一小段并比较，最后复核目录和元数据是否稳定。
5. 显示硬件静态首帧，以及硬件元数据中的整个动画大小和帧数。无法从硬件恢复原始视频的文件名。

识别流程只使用只读查询 `0x87`、`0x0C`、`0x0D`。它不调用完整动画读取，不启动 FFmpeg，不切换 `0x1E` 模式，也不暂停或退出官方进程。备份、写入及完整读回校验不受此项优化影响。

离线播放可能与素材读取竞争，因此首帧两次快照、包头目录及元数据都必须一致；任何格式、时序或一致性检查失败时拒绝显示，不使用官方素材替代。静态首帧表示硬件中保存的动画开头，不表示屏幕当前正在显示哪一帧，也不能证明官方实时传屏没有接管面板。
